# DESIGN — 줍줍 시리즈 통합 UI/UX

> v1.0 통합 앱 기준. Material 3 (기존 두 앱 동일 토대).

## 1. 화면 구조

```
┌───────────────────────────────┐
│  [홈] [수집 소스] [알림] [설정]   │  ← 기능 탭 (활성 서비스)
│                          ───── │
│                               │
│     활성 서비스의 화면 영역       │  ← 기존 Fragment 재사용
│     (mac_home / plan_home 등)  │
│                               │
│  ┌───────────┐ ┌───────────┐  │
│  │   맥줍줍   │ │   요금줍줍   │  ← 하단 서비스 네비 (2개)
│  └───────────┘ └───────────┘  │
└───────────────────────────────┘
```

## 2. 네비게이션
- **하단 네비**: 서비스 선택 (최대 5개, 신규 서비스 추가 시 탭 추가)
  - 아이템: `맥줍줍`(mac) / `요금줍줍`(plan)
- **기능 탭**: 앱바 하단 TabLayout
  - `홈` · `수집 소스` · `알림` · `설정` (각 서비스 fragment 재사용)
- 서비스 전환 시 기능 탭은 해당 서비스의 fragment로 교체 (백스택 미사용, commitNow)

## 3. 상태 표시
- 각 서비스 홈에서 포트·실행 상태·포털 URL 표시 (기존 UI 유지)
- 통합 설정 탭: 서비스별 설정 진입 (앱 전역 설정 + 서비스별 설정)

## 4. 테마·아이콘
- 앱 전역: `Theme.JupJup` (MacJupJup 테마 기반, Material3 DayNight)
- 런처 아이콘: 통합 `ic_launcher` (app 모듈 전용)
- 색상 카테고리: 기존 5색(seed_primary/status_*) 유지 → app 공용 `colors.xml`

## 5. 리소스 접두사 (필수, 충돌 방지)
- 서비스 모듈 리소스: `mac_*` / `plan_*`
- 예: `strings→mac_app_name_full`, `layout→mac_fragment_home`, id→`mac_nav_home`
- app 공용은 접두사 없음 (테마/아이콘/공통문자열)

## 6. 알림
- 채널: `jupjup_mac_server`, `jupjup_plan_server` (FGS dataSync)
- 서비스별 알림 실제 수신 구분

## 7. 참고
- 기존 두 앱의 화면·동작은 1:1 유지 목표 (신규 UX 구조만 도입)
- 폰트/간격 등 디테일은 기존 각 앱 스타일 존중
