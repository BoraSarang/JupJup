# BACKLOG — 유예 항목 기록

> 손댈 수 없거나 보류한 항목을 계속 남겨두는 기록. 해소 조건이 생기면 TODO로 승격.
> 최종 정리: 2026-09-22.

## 1. R30 구조 공통화 잔여 (설계 필요)
- 대상: `HttpServerService` 4벌·`Scheduler/Worker`·`NotificationService` 3벌·`CrawlHttp` 3벌
- 사유: 겉은 비슷하나 골격이 다름. 스케줄러는 소스/보드 단위 상이,
  CrawlHttp는 community에 EUC-KR 판정·썸네일 프록시가 붙음, 알림은 엔티티 상이,
  HttpServer는 포트·채널·라우트·Runtime이 얽힘. 합치면 수집·기동 동작이 바뀌는 rewrite급.
- 완료분: R37 수집예의·R38 로거/시간·R40 실패판정 (안전 조각만 승격)
- 재개 조건: 서비스별 동작 동결 테스트(실기 E2E) 확보 후 별도 설계

## 2. R28 커뮤니티 스크랩 (사용자 보류)
- 사유: 사용자가 "그닥 땡기지 않음"으로 보류. 보관기간(3/7/14/30/90일)이 대체 수단.
- 재개 조건: 사용자 요청 시

## 3. 수집 불가 소스 5곳 (기술적 불가)
- 에펨코/인스티즈: JS 보안월, MLBPARK: JS 렌더, SLR: URL 미확인, 판: 큐레이션형
- 사유는 코드·세션 로그에 기록됨. 비활성/제외 상태 유지.
- 재개 조건: 공식 API/RSS 제공 시

## 4. 커뮤니티 상세 셀렉터 잔재 다듬기 (제보 대기)
- 사유: 일부 셀렉터가 DevTools 복사 잔재로 과도하게 구체적일 수 있음.
  보드별 실측 없이 손대면 수집이 깨지므로 제보 들어오면 해당 보드만 수정.
- 재개 조건: 수집 실패·빈 본문 제보 시

## 5. R32 2단계 잔여 (사용자 A안 종결)
- 10분 FGS 루프·외부 LLM 분류 모두 현행 유지로 확정 (2026-09-22).
- 사유: 15분 주기로 신선도 충분, 키워드+첫문장 무료·예측 가능.
- 재개 조건: 분류 정확도 불만·속보성 요구 시

## 6. 커뮤니티 검색 FTS (과잉으로 보류)
- 사유: 수천 행 규모에서 `LIKE '%q%'`는 10ms대. FTS는 마이그레이션+검증 부담 대비 효과 미미.
  필터 경로는 v6 복합 인덱스로 절삭함.
- 재개 조건: 게시글 10만 건 이상 또는 검색 체감 저하 시
